Fix and redesign the complete "Forgot Password" and password reset flow to make it reliable, secure, and production-ready.

### Current Issue

The password reset link is being sent only once. After the first attempt, users are unable to receive a new reset link or successfully reset their password again.

### Required Fixes

#### 1. Multiple Password Reset Requests

* Users must be able to request a new password reset link whenever needed.
* Generating a new reset request should invalidate all previously generated reset links and tokens.
* Only the most recently generated reset token should remain valid.
* Old reset links must automatically become unusable.

#### 2. Secure Token Generation

* Generate a unique cryptographically secure token for every password reset request.
* Never reuse old tokens.
* Store tokens securely in the database.
* Hash tokens before storing them when possible.
* Prevent token prediction or brute-force attacks.

#### 3. Token Expiration

* Every password reset link must have an expiration time.
* Recommended expiration: 15–30 minutes.
* Expired links must display a clear message explaining that the link has expired.
* Users should be able to request a new reset link immediately.

#### 4. Email Delivery Improvements

* Ensure reset emails are sent every time a valid request is made.
* Prevent email delivery failures caused by stale tokens or incorrect state handling.
* Log email sending attempts and failures.
* Handle SMTP/API failures gracefully.
* Display appropriate success and error messages.

#### 5. Password Reset Flow

* User enters email address.
* System validates the account.
* System generates a new secure token.
* Previous reset tokens become invalid.
* New reset email is sent.
* User clicks the latest link.
* User sets a new password.
* Password is updated successfully.
* Token is immediately invalidated after successful use.

#### 6. Single-Use Reset Links

* A password reset link must work only once.
* After successful password reset:

  * Mark token as used.
  * Invalidate the token immediately.
  * Prevent reuse of the same link.

#### 7. Rate Limiting

* Prevent abuse of the forgot password feature.
* Example:

  * Maximum 3–5 reset requests within a short period.
  * Temporary cooldown after excessive requests.
* Show user-friendly messages when limits are reached.

#### 8. Security Enhancements

* Prevent account enumeration.
* Always return a generic response such as:
  "If an account exists for this email address, a password reset link has been sent."
* Log suspicious reset activity.
* Protect against brute-force attacks.
* Validate token ownership before allowing password changes.

#### 9. Database Improvements

Create proper fields for:

* reset_token
* token_created_at
* token_expires_at
* token_used
* reset_request_count
* last_reset_request_time

Ensure database records are updated correctly for every request.

#### 10. Error Handling

Implement clear handling for:

* Expired links
* Invalid tokens
* Already-used tokens
* Missing tokens
* Email delivery failures
* Database errors
* Network failures

Provide meaningful user-facing messages and detailed server-side logs.

### Expected Result

The forgot password system must allow users to request new reset links multiple times, invalidate old links automatically, send emails reliably on every request, enforce token expiration and single-use behavior, prevent abuse, and maintain enterprise-level security and reliability.
